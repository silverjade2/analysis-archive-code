# accident-definition-robot-fleet

[기기 사고 사전 탐지 1편: 무엇을 사고로 셀 것인가](https://analysis-archive.vercel.app/analyses/accident-definition-robot-fleet) 재현 코드.

실내 자율주행 로봇 fleet의 에러 로그에서 "사고"를 정의하고 집계 규칙을 만든 분석의 재현. 로그 대부분이 주행 판단 기록이라 총량이 장애 지표가 못 되고, 관제 대응 등급으로 정의한 타깃은 등급 정책이 바뀔 때 끊기며, 사고율 하락은 설치 초기 기기의 비중이 줄어서 생긴 것이라는 세 가지를 가상 로그로 다시 본다. 실제 로그는 없고 구조(주행 기록 비중, 첫 30일 위험 배수, 코드 분리 시점, 등급 변경 횟수)만 옮김.

## 실행

```bash
pip install -r requirements.txt
for s in scripts/0*.py; do python "$s"; done
```

1분 안쪽. numpy 2.5.3, pandas 3.0.6, matplotlib 3.11.2, pillow 12.3.0, Python 3.14. 같은 환경에서 두 번 돌려 결과 CSV와 생성 데이터가 byte 단위로 같았음.

## 스크립트

| | 역할 | 주요 출력 |
|---|---|---|
| 01 | 기기 1,200대, 10개월 이벤트 로그 생성. 설치가 초기에 몰린 fleet, 주행 기록 4종, 첫 30일 사고 hazard 2배, 사고 뒤 재발, 7월 들림/낙하 코드 분리, 등급 두 번 변경, 설치 전 검사 로그 | `data/devices.csv`, `events.csv.gz` |
| 02 | 코드별 행 수, coverage, 3단계 비중 | `code_profile.csv`, `tier_share.csv`, `category_share.csv` |
| 03 | 전도/낙하 로그의 월별 등급 구성, 등급 1 기준과 코드 기준의 월별 건수 | `level_timeline.csv`, `definition_compare.csv` |
| 04 | 간격 분포, X 민감도, 사건 묶기, K 민감도, 전도/낙하 따로 센 값과 함께 센 값, 로그 행에서 사고까지 퍼널 | `gap_bins.csv`, `x_sensitivity.csv`, `k_sensitivity.csv`, `joint_vs_separate.csv`, `funnel.csv`, `accidents.csv` |
| 05 | 월별/경과별/코호트별 사고율, 들림 포함 판, SIR, 경과 구성만으로 기대되는 사고율과 구성 효과 몫 | `monthly_rate.csv`, `tenure_rate.csv`, `cohort_rate.csv`, `sir.csv`, `mix_share.csv` |
| 06 | ground truth 평가. K별로 센 사고에 실제 사고/들림이 몇 건인지, 전도 코드에 섞인 들림 비중, 실제 사고의 SIR과 구성 효과 몫 | `eval_*.csv` |
| 07 | 그림 8장. 7은 코드별 coverage x 기기당 행 수, 8은 전달용 여섯 칸 요약 | `outputs/figures/site/fig1~8` |

`truth_*` 열은 판정(02~05)에 쓰지 않음. 04는 06 평가용으로 사건마다 `truth_kinds`를 실어 둘 뿐이고, 묶기와 K 판정은 시각과 코드만 봄.

X는 전도 120분(간격 분포의 valley), 낙하 360분(valley가 없어 1시간~1일 격자의 가운데). 전도 사건과 낙하 사건이 Y(120분, 전도 X 준용) 안에 이어지면 한 사건으로 합침. 둘이 하루 안에 이어지는 경우가 드물어 효과는 작고, 재현에서는 K 없이 센 사건 수가 따로 센 합과 같음.

## 확인할 숫자

- 02: 주행 4종이 로그의 89.4%, 사고 코드 0.40%. 3단계 코드 수 A 17.5 / B 62.5 / C 20.0%, 로그 0.5 / 7.9 / 91.6%
- 03: 등급 1 기준 사고는 8월 전 0건, 8월부터 145건. 코드 기준은 1월부터 104~292건
- 04: 로그 2,150행 -> 사건 1,362 -> 사고 867 (K14). K 없음에서 한 기기 최다 11건, K14에서 5건. X를 60분이나 180분으로 바꿔도 사건 수 차이 1% 안쪽
- 05: 전체 3.27 (기기 1,000대당 하루). 첫 30일 7.25. 7월 코드 분리에서 기본 판만 4.37 -> 2.20, 들림 포함 판은 3.55
- 05: 2~5월 사고율 5.87 -> 3.74, 경과 구성만으로 기대되는 값도 5.59 -> 3.31 (SIR 1.05~1.13)
- 05: 2~3월 -> 9~10월 하락(5.06 -> 2.25)의 구성 효과 몫 80% (기대 사고율 하락 / 실제 하락). 들림 포함 판 101%
- 06: ground truth 사고의 월별 SIR 0.76~1.23. 위험을 달력 시간에 불변으로 넣어도 이만큼 흔들림. 구성 효과 몫은 95%
- 06: K14 사고 867건 중 들림만 있는 사건 216건 (24.9%)

구성 효과 몫은 기대 사고율로 잼. Kitagawa 분해는 뺐음. 2~3월에는 90일 넘은 기기가 없어 두 기간이 공유하는 경과 구간이 거의 없고, 빈 구간을 사고율 0으로 채우면 비율 효과가 한쪽으로 쏠림 (seed를 바꿔 돌리면 ground truth에서도 +0.4~+3.0).

## 알려진 문제

- 들림 뒤 충전/대기 전환 같은 상태 로그는 넣지 않았다. 들림과 사고를 가르는 규칙은 다음 편 범위
- 노출이 달력일이라 전원을 끄고 쓰는 기기가 없다. 실제 fleet 보다 분모가 깨끗함
