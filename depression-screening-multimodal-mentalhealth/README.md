# depression-screening-multimodal-mentalhealth

가상데이터로 재현한 "발화 기반 우울 스크리닝" 파이프라인. 글은 [analysis-archive](https://analysis-archive.vercel.app)에 있다.

## 왜 가상데이터인가

원본 프로젝트(2024 상반기)는 번아웃을 겪는 직장인이 자기 말로 우울을 조기에 알아차리게 하는 서비스를 설계하고, 한국어 우울 분류 모델과 감정 분류 모델을 만들었다. 이 저장소는 그때 쓴 데이터를 그대로 쓰지 않는다. AI-Hub의 두 공개 데이터셋 **스키마**만 가져와 같은 모양의 데이터를 생성하고, 그 데이터로 스크리닝 파이프라인을 처음부터 다시 설계한다.

- **정신건강진단 및 예측을 위한 멀티모달 데이터** (전남대학교병원, 2021) — 참가자 2,000명이 음성 과제 8개를 수행한 18,000건. wav + STT 텍스트, PHQ-9 점수와 2단계 클래스(정상 / 우울한 기분), 환자군·대조군, 성별, 나이. 공개 기준 환자군 56.5%, 우울 클래스 41.8%, 여성 64.7%. 안심존에서만 접근할 수 있는 보건의료 데이터다.
- **감성 대화 말뭉치** (미디어젠, 2020) — 6대 감정(기쁨·슬픔·분노·불안·당황·상처)과 상황·연령대가 붙은 대화 코퍼스.

생성 데이터는 참가자 2,000명 × 과제 8개 = 16,000 녹음(라벨링 데이터 18,000건 중 임상 2,000건을 뺀 음성 16,000건에 대응)과 감정 문장 24,000개다. 실제 데이터의 값이 아니라 실제 데이터의 **구조**를 재현한다.

## 데이터에 심어둔 구조

이 데이터로 모델을 만들면 반드시 마주치는 세 가지를 생성기에 넣었다.

1. **참가자 누수.** 한 사람이 8건을 녹음한다. 음색 계열 피처(MFCC, f0)는 사람 안에서 안정적이고 녹음 간 변동이 작다. 녹음 단위로 랜덤 분할하면 같은 사람이 학습과 평가 양쪽에 들어간다.
2. **그룹 ≠ 라벨.** 환자군에도 치료 중이라 PHQ-9가 낮은 사람이 있고(351명), 대조군에도 높은 사람이 있다(51명). 환자군은 면담에서 약·진료·선생님 같은 치료 맥락을 자주 말한다. 라벨을 "환자군 여부"로 두면 모델이 그 어휘를 배운다.
3. **과제별 신호 분포.** 숫자 세기와 낭독은 모든 참가자의 텍스트가 같다. 텍스트 채널은 그 과제에서 아무 정보가 없고 음성만 남는다. 서술 과제 5개는 반대다.

`truth_*` 컬럼(템플릿 가중치, 치료 언급 여부)은 생성기의 잠재 변수다. 채점과 진단에만 쓰고 어떤 모델에도 피처로 넣지 않는다. `99_verify.py`가 매 실행마다 확인한다.

## 실행

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cd pipeline && for s in 0*.py 1*.py 9*.py; do ../.venv/bin/python "$s"; done
```

Apple Silicon 기준 약 35분. 대부분 06의 시드 3개 × 분할 2종 × 모델 4종 교차검증이다. 시드 42 고정. 스크립트는 `pipeline/` 안에서 실행한다(`_path.py`가 `src/`를 import 경로에 넣는다).

환경: Python 3.14.6, numpy 2.4.4, pandas 3.0.2, scikit-learn 1.8.0, scipy 1.17.1, matplotlib 3.10.8, kiwipiepy 0.23.2, Pillow 12.3.0 (macOS 15, arm64). 이 조합에서 `data/`와 `outputs/`를 지우고 다시 돌려도 CSV와 그림이 byte 단위로 같다.

## 구성

```
src/        config.py     경로·시드·생성 파라미터·과제 정의
            lexicon.py    문장 템플릿과 슬롯 풀, 감정 코퍼스 사전
            textgen.py    서술 과제 STT 생성 (PHQ z에 따른 템플릿 선택, 말버릇, STT 오인식)
            audiogen.py   음향 피처 20차원 생성 (화자 지문 + 과제 효과 + 우울 효과 + 잡음)
            features.py   Kiwi 형태소 토큰화, 치료 어휘 마스킹
            models.py     텍스트(형태소 TF-IDF + LR), 음성(GBM), 융합(채널 확률 late fusion)
            evalutil.py   녹음/참가자 단위 교차검증, 지표, 참가자 단위 집계
pipeline/   01~11, 99     아래 표
```

| 스크립트 | 역할 |
| --- | --- |
| `01_generate_cohort.py` | 참가자 2,000명. 그룹·성별·나이·직장인 여부·PHQ-9·라벨 |
| `02_generate_recordings.py` | 녹음 16,000건. STT 텍스트와 음향 피처 |
| `03_generate_emotion_corpus.py` | 감정 문장 24,000개 (6감정 × 상황 7종) |
| `04_tokenize.py` | Kiwi 형태소 토큰화 캐시 |
| `05_eda.py` | 코호트 구조, 과제별 통계, 치료 언급률, 음향 피처 분산 분해 |
| `06_split_comparison.py` | 녹음 단위 랜덤 vs 참가자 단위 분할 × 텍스트/음성 GBM/음성 k-NN/융합, 시드 3개 |
| `07_task_ablation.py` | 과제 하나씩만 쓴 AUC, 참가자 단위 집계 범위 비교 |
| `08_group_vs_phq.py` | 환자군 라벨 vs PHQ 라벨, 치료 어휘 마스킹 |
| `09_emotion_transfer.py` | 감정 분류기 성능과 그 점수를 스크리닝에 전이했을 때 |
| `10_interpretation_subgroups.py` | 상위 피처 유형, 하위군 AUC(부트스트랩 CI), 보정 |
| `11_figures.py` | 그림 8장 |
| `99_verify.py` | 누수 점검, 상한 확인, 글에 쓸 숫자 manifest 생성 |
| `12_site_figures.py` | 같은 8장을 사이트 톤으로. 값은 CSV에서 읽고 다시 계산하지 않는다 (`sitestyle.py` 공용) |
| `13_widget_data.py` | 사이트 위젯용 `split_comparison.json` |

결과는 `outputs/results/*.csv`, 그림은 `outputs/figures/*.png`, 사이트용 webp와 png는 `outputs/figures/site/`. 글에 쓰는 모든 숫자는 `outputs/results/number_manifest.csv`에 있다.

제대로 돌았는지 확인할 숫자: `split_comparison.csv`에서 speaker_prior의 참가자 AUC 1.0 (녹음 랜덤 분할이면 참가자 신원만으로 다 맞힌다는 뜻), 음성 k-NN의 참가자 AUC가 녹음 랜덤 0.9271에서 참가자 분리 0.8394로 떨어지고 텍스트는 0.9314에서 0.9304로 거의 안 움직인다.

`data/`는 커밋한다. 코드를 돌리지 않아도 생성 데이터를 열어볼 수 있게 하기 위해서다. 생성기를 고치면 파이프라인 전체를 다시 돌려 데이터와 결과를 같은 커밋에 넣는다.

## 남은 것

- Kiwi 형태소 분석 결과가 플랫폼에 따라 다르다. 같은 kiwipiepy 0.23.2인데 Linux(Python 3.12)에서 만든 토큰 캐시와 macOS에서 만든 캐시가 녹음 16,000건 중 1,179건에서 달랐다("창 밖"이 "창밖"으로 붙는 식). 01~03의 생성 데이터는 같고 04부터 갈린다. 그래서 텍스트가 들어가는 AUC는 셋째 자리에서 움직이고, 감정 전이 AUC는 0.6106에서 0.6263으로 둘째 자리에서 움직인다. 커밋된 `data/`와 `outputs/`는 macOS 기준이다.
- 원본 그림(`11_figures.py`)은 Noto Sans CJK를 찾고, 없으면 AppleGothic으로 간다. 둘 다 없는 환경에서는 한글이 깨진다.
